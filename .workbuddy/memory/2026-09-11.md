## 云图库前端搭建（yu-picture-frontend）

**背景**：后端 `C:\Users\SPHZ\Desktop\Code\Java\yu-picture-backend`（Spring Boot，context-path `/api`，端口 8080）已具备用户/图片/空间/空间分析四大模块共 34 个接口。前端原本是空的 Vite 脚手架，本次从零搭建完整前端。

**技术选型**（沿用脚手架已有依赖 + 增补）
- Vue 3.5 + Vite 5 + TypeScript 5.7 + Pinia + Vue Router
- ant-design-vue 4.x + @ant-design/icons-vue（新增）
- echarts（新增，用于空间分析图表）
- dayjs（新增，显式声明；原先只是 antdv 的传递依赖）

**架构**
```
src/
  request.ts                 axios 实例，baseURL=/api，withCredentials，响应拦截解包 BaseResponse
  api/                       按后端 Controller 分文件（user/picture/space/spaceAnalyze/file），typings.d.ts 定义全局 API 命名空间
  constant/                  picture.ts（审核状态）、space.ts（等级/类型/配额）
  stores/useLoginUserStore   登录态（Session Cookie，刷新后重新拉取）
  access.ts                  全局路由守卫：首屏拉登录态、requiresAdmin / requiresLogin
  layouts/                   BasicLayout（顶栏+内容+页脚）、UserLayout（居中卡片）
  components/                GlobalHeader、PictureList、PictureSearchForm、PictureUpload、AdminTabs、analyze/(BaseChart, SpaceAnalyzePanel)
  pages/                     HomePage、PictureDetailPage、SearchPicturePage、AddPicturePage、AddPictureBatchPage、
                             MySpacePage、AddSpacePage、SpaceDetailPage、SpaceAnalyzePage、
                             user/(Login, Register)、admin/(UserManage, PictureManage, SpaceManage, SpaceAnalyzeAll)、exception/NotFound
```

**关键约定**
- Vite 代理 `/api` → `http://localhost:8080`，**不 rewrite**（后端 context-path 就是 `/api`），走代理后同源，Session Cookie 正常携带
- 后端 `JsonConfig` 把 Long 序列化为 String，前端所有 id/容量/数量按 string 处理
- `vite.config.ts` 增加 manualChunks 拆分 vue / antd / echarts

**踩坑记录**
1. `@tsconfig/node22` 声明 `lib: ["es2024", ...]`，而脚手架装的 typescript 是 ~5.6.3 → `TS6046`。升级 typescript 到 ~5.7.3 + vue-tsc 到 ^2.2.10 解决。
2. 后端 **PictureVO 没有 reviewStatus 字段**（只有实体 Picture 有），所以「空间详情页展示审核状态」做不了；审核状态只在管理端（走 `/picture/list/page` 返回实体）可见。
3. `SpaceAnalyzeQueryRequest.startTime/endTime` 是 `java.util.Date` 且**没有 @DateTimeFormat**，Spring 默认用 locale 相关的 DateFormat.SHORT 解析，格式不确定 → 前端未启用自定义时间范围，只用后端默认「最近 30 天」，仅暴露 granularity 切换。
4. `/picture/list/page/vo` 不传 spaceId 时后端强制 `reviewStatus=PASS`，管理员看不到待审核图 → 管理端必须用 `/picture/list/page`（管理员专属，返回实体）。

**⚠️ 重要环境问题**：本机**正在运行的后端进程是旧构建**——`/api/space/**`、`/api/space/analyze/**` 全部返回 404，但源码和 `target/classes` 里 SpaceController / SpaceAnalyzeController 都在（编译于 9/6）。需要重启后端才能让空间相关页面生效。用户/图片模块（tag_category、list/page/vo 等）正常，公共图库已能拉到真实数据。

## 追加：定位「我的空间」页面 HTTP 404 的老巢

用户反馈「我的空间」页弹出 `请求失败（HTTP 404）`，并且页面底部显示误导性的「你还没有创建任何空间」。

**根因（已确证）**：跑在 8080 上的 java 进程（PID 26608，21:17 启动）用的 classpath 是
`C:\Users\SPHZ\WorkBuddy\Worktrees\yu-picture-backend\main-f92bec67\target\classes`
—— 一个 **WorkBuddy 自动创建的 git worktree**，分支 `workbuddy/main-f92bec67`，HEAD = `bd4cf62`（2026-01-18「用户传图」）。

而主仓库 `C:\Users\SPHZ\Desktop\Code\Java\yu-picture-backend` HEAD = `f93a9ea`（2026-09-11「feat(space): 空间模块与图库分析」），正是 `bd4cf62` 的**下一个提交**。

即：**后端跑的是旧 worktree 的构建产物，缺少整个空间模块**，所以 `/api/space/**` 全部落到容器级 404（返回 Spring Boot 默认的 `{"timestamp","status":404,"error":"Not Found","path"}`，而不是应用自己的 `BaseResponse`）——这一点是区分「路由不存在」和「业务报错」的关键判据。

**已做的前端加固**（不管后端咋样，接口挂了不能再冒充空数据）：

- 所有列表请求补 `catch`，消除 unhandled promise rejection
- `type-check` 复验通过
